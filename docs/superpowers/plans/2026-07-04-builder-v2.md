# Builder v2 + Frontend Polish — Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the admin builder into an Alovio-branded WYSIWYG editor with live conditional simulation, and polish the checkout-facing rendering (styling + half-width layout), shipping as v1.1.0.

**Architecture:** UI-layer rebuild only — option storage, REST, ConditionalLogic engine, PHP renderers, and Store API integration are unchanged. The preview canvas reuses the shipped `buildValues` + `activeMap` JS engine so the simulation is provably identical to the live checkout. Two small server-side additions: FieldSchema `width` property and a ClassicRenderer grid wrapper + `assets/css/frontend.css`.

**Tech Stack:** React via `@wordpress/scripts` + `@wordpress/data` (existing store), plain CSS with design tokens (flame `#f97316`/`#ea580c`, coal `#1c1917`, warm grays), PHPUnit + Brain Monkey, Jest, wp-env + Playwright live QA.

**Spec:** `docs/superpowers/specs/2026-07-04-builder-v2-design.md`
**Visual contract:** `docs/mockups/builder-v2.html` (approved mockup — layout, spacing, palette, component shapes come from here)

public function test_width_normalized(): void {
    $out = FieldSchema::normalize( array( 'fields' => array(
        array( 'id' => 'a', 'type' => 'text', 'width' => 'half' ),
        array( 'id' => 'b', 'type' => 'text', 'width' => 'bogus' ),
